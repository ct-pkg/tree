## 裁定

1. **归属**：新建 `ct/tree` 独立包，不进 `std`、不进 `ct/json`；JSON / XML 各自定义节点枚举。
2. **层次**：本包只做存储与门面，不定义节点枚举。`kind` 按存储形状定义为
   「标量叶 / 有序孩子 / 键值孩子 + 类型签」；格式层只做 `enum ↔ Node` 两个薄转换，
   缺失语义留在转换层。**`kind` 枚举不得出现格式专属名字。**
3. **存储**：节点内不嵌 `Vec` / `Map`；节点只存 `{kind, type_sig, payload_index, count}`，
   孩子下标数组与键值对数组全部从 arena 分配。解析实现用「暂存 `Vec` → 冻结进 arena」，
   分块增长仅作流式场景备选。「整树一次 `free_all`」是唯一释放协议。
4. **泛型入口**：`as<T>` / `to<T>` 直达泛型，不提供公开的具体函数面板。依赖语言侧
   「泛型入口三件套」ADR（impl 内泛型方法、跨单元实例发射 + 链接策略、限定调用携带类型实参），
   走正规新特性流程。`as_User` / `to_User`、`decode` / `encode` 仍由 schema 生成器产出，形态不变。
5. **迭代门面**：本包提供 `length()` / `at(i)` / 键值入口，命名按未来语言迭代协议会消费的形态；
   文档不写「过渡」。用户类型迭代协议另立 LANG issue，不随本批。
6. **绑定点裸写糖**（`Vec<int> v = node;`）与三件套不是同一特性，另立姊妹卡，不随本批。
7. **排期**：`v0-PH-0` 落仓库骨架与治理；`v0-PH-1` 落树容器，分 S1 存储与解析、
   S2 迭代门面与生成器、S3 泛型 `as<T>` / `to<T>`。卡收口在 S3，S1/S2 日历解耦。

## 理由

- 节点语义格式专属（null / 空元素 / 锚点 / 日期不可混为一谈）；共享枚举会让任一格式的变体
  变更变成全体破坏性变更，且永久关闭「在 tree 之上加共享语义层」的选项。
- 节点内嵌 `Vec` / `Map` 会在 ADT 无 drop glue、容器字段无自动胶水的前提下，把
  「一次 `free_all`」降级为书写者纪律。
- 泛型方法、跨单元实例、限定调用三件缺一，库都无法对外提供 `as<T>`；拆开做会留下
  三种半成品形态。
